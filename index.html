Github AI 插件装前自检

贴 GitHub 链接 → 只读拉取代码 → 出六问结论。全程不安装、不构建、不执行被检代码。
不填 Token 时 GitHub API 限额 60 次/小时（按 IP 算，同一网络共用）。额度用尽会自动切到 jsDelivr，或直接勾选上面的零额度模式。

扫描过程

使用教学

一、三步上手

  1. 把插件的 GitHub 网址贴进第一个输入框，支持三种写法：
    • https://github.com/作者/仓库 —— 审整个仓库
    • https://github.com/作者/仓库/tree/main/plugins/xxx —— 只审某个子目录
    • https://github.com/作者/仓库/releases/tag/v1.0.0 —— 审默认分支（版本号会记进报告）
  2. （可选）填 GitHub Token，见第二节。不填也能用，只是次数少。
  3. 点「开始体检」，等 5~20 秒，报告最上面第一行就是结论。

二、GitHub Token 怎么弄（30 秒）

Token 只用来提高 API 调用次数，不填也能跑。读公开仓库一个权限都不用勾。

  1. 登录 GitHub，打开 github.com/settings/tokens
  2. 点 Generate new token → 选 Generate new token (classic)
  3. Note 随便写，比如 plugin-guard；Expiration 选 7 天或 30 天
  4. Scope（权限勾选项）一个都不要勾 —— 读公开仓库不需要任何权限
  5. 拉到最下面点 Generate token
  6. 复制 ghp_ 开头那一串，粘贴到本页第二个输入框
安全提示：Token 只存在浏览器内存里，刷新页面就没了，不写磁盘、不发送到任何第三方。
不要贴进聊天记录、不要 commit 进仓库、不要截图外发。不用了就在 GitHub 设置页点 Delete 立刻作废。

填了之后：60 次/小时 → 5000 次/小时，一次体检大约消耗 5 次。

三、两种模式怎么选

场景建议
网络正常、额度够默认模式。能拿到 commit sha、star 数、同名对照与差分
报 403（额度用完）什么都不用做，会自动切到零额度模式
GitHub 连不上，或不想消耗额度勾选「零额度模式」，全程走 jsDelivr

零额度模式的代价：拿不到 star、创建时间、fork/归档状态，也做不了同名对照。代码层的检查一项不少。

四、结论四个档怎么读

A可以装。代码里没有外发、没有读凭据、没有动态执行。
B可以装，但要关开关。通常是遥测、定时器，或连了预期内的域名。
C不建议装。有硬信号：动态执行、未知外发域名、读取凭据、只有压缩产物。
D不要装。凭据读取与外发闭环、远程加载执行、安装期下载执行。

五、报告先看哪三处

  1. 第一行结论和下面的「依据」—— 一句话说清为什么是这个档
  2. 外发域名清单—— 标「非预期」的就是它连了不该连的地方
  3. 不可判定—— 诚实清单：静态分析看不出运行时行为、服务端下发、加密载荷内容。没有这一栏的报告不要信。

六、常见报错

403API 额度用完。等一小时、填 Token，或勾零额度模式
404仓库不存在、地址拼错，或私有仓库
文件读取失败网络抖动。报告里会列出失败的文件，并提示结论可能不完整
jsDelivr 找不到仓库默认分支不是 main/master。在链接里写明分支再试
这个工具只读不跑：不 clone、不 npm install、不执行被检代码的任何一行。
它的结论是「证据 + 判断」，不是安全保证。
