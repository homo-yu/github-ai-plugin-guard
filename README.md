# Github AI插件装前体检（Plugin Guard）

贴一个 GitHub 链接，在**安装之前**判断这个插件能不能装。单文件 HTML，双击打开即用，无后端、无依赖、无构建。

## 它怎么工作

```
GitHub URL → 元数据 → 定位 commit → 文件树 → 选文件 → 静态规则 → 同名对照 → 报告
```

**硬约束：只读。** 不 clone、不 `npm install`、不 build、不执行被检代码的任何一行。
安装脚本本身就是攻击面，所以"运行一下看看"这条路从设计上就被堵死。

## 判定四档

|档|含义|触发条件（摘要）|
|-|-|-|
|A|可以装|代码里无外发、无凭据读取、无动态执行|
|B|可装但需限制|有网络请求（域名在预期内）或定时器/自动钩子|
|C|不建议装|动态执行、未知外发域名、读凭据、只有压缩产物|
|D|不要装|凭据读取与外发闭环、远程加载执行、安装期下载执行|

不做加权总分：**硬拦截优先**。单条"读了环境变量"是正常行为，单条"有 fetch"更是遍地都是，
只有 **凭据读取 × 网络外发出现在同一个文件**，才升级为硬拦截。

## 报告里有什么

1. 审的是哪个 commit（sha + 时间，可复核）
2. 六问：发什么数据到哪 / 读不读文件密钥 / 有无加密执行 / 安装期行为 / 自启动 / 结论
3. 同名对照：同名仓库按 star 排序，**star 最多的那个当"官方初版"**，其余按仿冒看待
4. 目录页提醒：改名/转让、fork、归档、无 License、刷星嫌疑、文件读取失败
5. 与官方初版的差分：文件重合度、多出/缺少的文件
6. 外发域名清单（只统计代码；README 和 package.json 元数据里的链接单独列出，不参与判定）
7. 证据卡：`规则ID · 文件:行 · 原文片段 · 处理建议`
8. 不可判定：运行时行为、服务端下发、加密载荷内容、未下载文件、依赖树

## 使用

1. 双击 `index.html`（Chrome / Edge）
2. 贴链接，例如 `https://github.com/owner/repo` 或 `https://github.com/owner/repo/tree/main/subdir`
3. 可选：填一个 GitHub Token（只存在内存里），额度从 60 次/小时提到 5000

## 数据源（两种模式）

|模式|用什么|消耗|拿得到|拿不到|
|-|-|-|-|-|
|默认|GitHub REST API + raw|60 次/小时（按 IP，同一网络共用）|commit sha、star、创建时间、fork/归档/License、同名对照与差分|—|
|**零额度**（勾选框）|jsDelivr（`data.jsdelivr.com` + CDN 镜像）|0（不碰 GitHub API）|文件树、文件内容、全部代码层规则|star（只有徽章近似值）、创建时间、fork/归档/License、同名对照|

额度用尽时**自动**切到零额度模式，不用手动勾。国内网络下 `raw.githubusercontent.com` 经常不通，
`cdn.jsdelivr.net` 也常被墙，所以代码里内置了镜像轮询：`cdn → fastly → testingcf → gcore`，命中一个就记住。

## 自测

```bash
node \\\_test.mjs          # 单元测试：URL 解析、名称相似度、规则正则、分档逻辑
node \\\_fixture-test.mjs  # 端到端：用假网络跑完整流水线，不消耗额度
```

## 已知局限

* 静态代码看不出运行时行为，只能推断；报告里专门有一栏"不可判定"
* 服务端下发无法检测：插件先连 A，之后听 A 的话，静态只能看到那个 loader
* 加密载荷只做熵检测，不解密（解密就要执行，违反原则）
* 不展开 `node\\\_modules`，第三方依赖中的后门不在范围内
* 同名检索依赖 GitHub Search API，同名但命名差异大的仓库可能漏掉
